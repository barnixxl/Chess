# Архитектура приложения

## 1. Основные модули

### 1.1. Game
- Хранит всё состояние партии: доска (`board`), история ходов, флаги игрока-человека для белых/чёрных.
- Вычисляет производные значения: чей ход, проверки, маты и др.
- Вся логика шахматных правил реализована здесь; UI работает только с публичным API и не знает о шахматных правилах.  
  _Файл: Chess/Game.swift_

### 1.2. ViewController
- Основной UI-слой.
- Держит экземпляр `Game`, синхронизирует его с `BoardView`, обрабатывает пользовательские действия, показывает алерты, вызывает сохранение/загрузку (Application Support/game.json).
- Вся логика отображения и реакций на пользовательский ввод здесь.  
  _Файл: Chess/ViewController.swift_

### 1.3. BoardView
- Полностью кастомная вьюха для отрисовки клеток, фигур, подсветки возможных ходов, обработки тапов по клеткам.
- Экземпляр обновляется через публичные свойства: `board`, `selection`, `moves`. Отображение черных/белых, тема доски берутся из `Storage`.
  _Файл: Chess/BoardView.swift_

### 1.4. Настройки и дополнительные экраны
- Реализованы программно, с помощью `UITableView` в `SettingsViewController`.
- В `Main.storyboard` только основной экран с `ViewController`, аутлетами и базовой структурой сцены.
- Настройки и вспомогательные экраны не используются через Interface Builder, а строятся кодом.

---

## 2. Искусственный интеллект (ИИ)

- Весь ИИ реализован в методе `nextMove(for:)` класса `Game`.
  - Получение списка всех допустимых ходов, фильтрация невозможных (оставляющих короля под шахом).
  - Оценка ходов по материалу, потенциальным промоциям, угрозам, возможным потерям и пр.
  _См.: Chess/Game.swift (стр. 233:314)_

- Ход компьютера инициируется из метода `makeComputerMove()` в `ViewController`:
  - Если текущий игрок — не человек (`playerIsHuman()`), вызывается `nextMove(for:)` и сразу выполняется ход.
  - Этот механизм вызывается после каждого валидного хода и при смене типа игрока (Human/Computer) в интерфейсе.
  _См.: Chess/ViewController.swift (стр. 218:287)_

- ИИ интегрирован только логически: UI запрашивает решение у движка при необходимости, сторонние библиотеки не используются.

## 3. Экран настроек

- Экран настроек создаётся вручную: метод `settings()` в `ViewController` открывает его с помощью `present(SettingsViewController(), animated: true)`.
- Настроек в storyboard нет.
- `SettingsViewController` регистрирует `UITableView` программно, делит её на секции "Settings" и "Themes".
- При выборе темы обновляется значение в `Storage.shared.boardTheme` и через callback (`onThemeSelect`) применяется к `BoardView`.
  _См.: Chess/SettingsViewController.swift (стр. 5:104)_

- Хранилище (`Storage`) — обертка над `UserDefaults`, все значения подтягиваются на старте приложения и сразу влияют на отображение (например, переворот доски при игре черными).
  _См.: Chess/Storage.swift (стр. 4:28)_

- Таблица настроек формируется программно в `viewDidLoad`. В storyboard её нет.

## 4. Регистрация и авторизация (добавление)

**На текущий момент** в проекте отсутствует логика авторизации и сетевые взаимодействия.

### Как добавить:

#### 4.1. Структура
- Вынести начальный поток в отдельный координатор/роутер (например, `AuthCoordinator`), который решает: показывать ли экран логина или основной экран игры (ViewController).
- Альтернативно: после создания `UIWindow` в `SceneDelegate` проверить статус пользователя и установить соответствующий `rootViewController` (`AuthViewController` или `UINavigationController` с шахматами).

#### 4.2. Создание экранов
- Реализовать два контроллера: `LoginViewController` и `RegisterViewController` с использованием `UIStackView` и `UITextField`. Сделать их в XIB или программно (аналогично настройкам).
- Если требуется storyboard — вынести в отдельный файл (`Auth.storyboard`) и подключить к `SceneDelegate`.

#### 4.3. Навигация
- При первом запуске показывать модально `AuthViewController` поверх главного меню (`ViewController`).
- После успешной регистрации — закрыть модальный контроллер и позволить пользователю играть.
- Вариант: сделать меню (`MainMenuViewController`) с кнопками "Играть", "Настройки", "Войти", и использовать его как корень приложения.

#### 4.4. Состояние авторизации
- Для хранения статуса авторизации: реализовать `AuthStorage`, или использовать Keychain, либо расширить Storage флагом `isLoggedIn`.
- При старте приложения проверять авторизацию и выбирать соответствующий сценарий показа экранов.

#### 4.5. Интеграция с UI
- UI/логика авторизации отделены от шахматной логики и ViewController.
- Для связи: можно использовать уведомления (например, `UserDidLogin`), на которые реагирует основной контроллер (сбросить партию, создать новую и т.п.).

#### 4.6. Практические шаги
- Начать с простого модального контроллера авторизации.
- Добавить кнопку "Profile" или "Login" на главный экран (Navigation bar / Settings).
- После входа сохранять токен, и на следующих запусках сразу переходить к ViewController.
